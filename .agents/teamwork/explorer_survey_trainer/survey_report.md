## 1. Введение и методологическая основа Вуковича

### 1.1. Проблема классических тактических тренажеров («Иллюзия одного хода»)
В традиционных шахматных онлайн-платформах (Lichess, Chess.com) подавляющее большинство задач на тему атаки на короля сводится к нахождению **первого эффектного хода** (например, классической жертвы слона $1.Bxh7+$). Как только пользователь делает жертву, задача засчитывается как решенная.

Это формирует у шахматистов (включая целевую аудиторию уровня 2000 Chess.com) критический методологический дефект: **«атакующий оптимизм» (Hope Chess)**. Игрок импульсивно отдает фигуру, надеясь, что мат «получится сам собой», не рассчитав форсированные ответы соперника на 3–7 ходов вперед.

В реальной партии после $1.Bxh7+\;Kxh7\;2.Ng5+$ позиция белых требует филигранной точности:
* Если черные отвечают $2...Kg6!$ (самое упорное сопротивление), белые обязаны заранее рассчитать длинную цепь: $3.h4!\;f5\;4.h5+\;Kh6\;5.Nxe6+\;Kh7\;6.Nxd8$ (выигрыш ферзя) или вскрытие вертикали «h». Нетерпеливый шах $3.Qh5?$ или $3.Qg4?$ немедленно губит атаку и оставляет белых без фигуры в проигранной позиции.
* Если черные отступают $2...Kg8$, атакующий обязан точно знать, проходит ли немедленный выпад $3.Qh5$, либо черные парируют угрозу ходом $3...Bxg5!$ или $3...Nf6$, и требуется предварительный тонкий маневр $3.Qd3!$ (батарея по диагонали b1–h7 с перекрытием слона c8).

### 1.2. Фундаментальные принципы Вуковича («The Art of Attack in Chess»)
Владимир Вукович в главе V своей монографии формулирует 5 обязательных условий корректности классической жертвы слона:
1. **Контроль ключевых полей вторжения**: белые должны иметь надежный доступ к пунктам $g5$ и $h5$ для коня и ферзя.
2. **Пешечный барьер (клин $e5$)**: пешка на $e5$ должна отрезать черного коня от защитного поля $f6$.
3. **Отсутствие легких фигур защиты на диагоналях**: слон или ферзь черных не должны иметь возможности комфортно разменять атакующего коня на $g5$ ($...Bxg5$) без фатального вскрытия вертикали $h$.
4. **Недостаток тяжелых фигур защиты на королевском фланге**: черная ладья $f8$ и ферзь $d8$ стеснены.
5. **Точный расчет всех 4 ветвей отступления короля**: $2...Kg8$, $2...Kg6$, $2...Kh8$, $2...Kh6$.

**Цель Тренажера глубокого расчета**: заставить пользователя рассчитать в уме и последовательно исполнить на доске **всю форсированную цепочку из 3–7 ходов**, получая немедленное тактическое опровержение при малейшей неточности.

## 2. Архитектура движка глубокого расчета (Deep Calculation Engine)

### 2.1. Концепция форсированной последовательности ходов
Каждое упражнение в тренажере представляет собой направленное дерево ходов (Directed Acyclic Graph), где:
* Узлы нечетной глубины (White plies) — это ходы пользователя, требующие нахождения лучшего решения.
* Узлы четной глубины (Black plies) — автоматические ответы системы за черных, выбирающие наиболее упорную и поучительную защиту.

```
       [Стартовая позиция перед жертвой]
                      │
                      ▼ 1. Bxh7+! (Жертва слона)
               [Позиция 1... Kxh7]
                      │
                      ▼ 2. Ng5+! (Подключение коня)
                      │
       ┌──────────────┴──────────────┐
       ▼                             ▼
  2... Kg8 (Отступление)       2... Kg6! (Королевский рейд - главное упорство)
       │                             │
       ▼ 3. Qh5! (или 3.Qd3!)         ▼ 3. h4! (Ключевой тихий/атакующий ход)
       │                             │
       ▼ 3... Re8                    ▼ 3... f5
       │                             │
       ▼ 4. Qxf7+ Kh8                ▼ 4. h5+ Kh6
       │                             │
       ▼ 5. Qh5+ Kg8                 ▼ 5. Nxe6+ Kh7
       │                             │
       ▼ 6. Qh7+ Kf8                 ▼ 6. Nxd8 (Выигрыш ферзя с матом)
       │
       ▼ 7. Qh8+ Ke7 8. Qxg7# (Мат)
```

### 2.2. Классификация ходов пользователя
В тренажере реализована 5-уровневая семантическая градация любого хода, сделанного пользователем:

| Категория | Внутренний тип | Оценка позиции | Поведение системы |
|---|---|---|---|
| **Лучший / Выигрывающий** | `best` | Сохраняет форсированный мат или решающий перевес (+M / > +4.5) | Засчитывается шаг, звуковой сигнал успеха, запускается авто-ответ черных |
| **Альтернативный допустимый** | `alternative` | Ведет к выигрышу с минимальной потерей темпа (разница $\le 0.5$ пешки) | Засчитывается, но выдается пояснение Вуковича о предпочтительной главной линии |
| **Неточность** | `inaccuracy` | Выигрыш сохраняется, но выпускается форсированный мат (переход в тяжелый эндшпиль) | Ход отменяется, выдается совет: «Выигрывает, но есть гораздо более форсированное решение» |
| **Зевок / Ошибка** | `blunder` | Атака захлебывается, белые теряют перевес ($\le 0.0$) или остаются без фигуры | **Запуск интерактивного опровержения**: черные делают карающий ход на доске с разбором |
| **Невозможный ход** | `illegal` | Нарушение правил шахмат (шах королю, перекрытая траектория) | Фигура возвращается на место (snapback), легкая анимация покачивания, счет не штрафуется |

## 3. Интерактивный механизм опровержения ошибок (Blunder Refutation)

### 3.1. Принцип работы опровержения
В отличие от стандартных тренажеров, где при ошибке просто загорается красный крестик («Неверно, попробуйте еще раз»), тренажер Вуковича **наглядно демонстрирует, почему ход плох**.

Когда пользователь совершает `blunder`:
1. **Фиксация хода пользователя**: Ход белых отображается на доске.
2. **Мгновенный контраргумент черных**: Движок автоматически делает сильнейший опровергающий ход черных с плавной анимацией (например, $3...Bxg5!$ или $3...Kxg5!$).
3. **Визуальные маркеры угрозы**: Поле ошибки подсвечивается полупрозрачным красным цветом, стрелкой цвета бургунди показывается линия опровержения.
4. **Окно тактического разбора (Refutation Modal / Callout)**:
   * **Заголовок**: «Ложный след: почему ход 3.Qh5? ошибочен»
   * **Тактическое объяснение на русском языке**: подробный комментарий, цитирующий логику Вуковича.
   * **Кнопка возврата**: «Понятно, вернуться к расчету» (восстанавливает позицию до ошибки).

### 3.2. База типовых ложных следов Вуковича

#### Пример 1: Преждевременный выпад ферзя при активном слоне черных
* **Позиция**: Черные сохранили слона на $c8$ или ферзя на $d8$, контролирующих диагональ $c1–h6$ и поле $g5$.
* **Ошибка белых**: $3.Qh5?$
* **Опровержение черных**: $3...Bxg5!$ (или $3...Qxg5!$)
* **Объяснение**: *«Грубая ошибка! Вы поторопились с ходом ферзя. Черный белопольный слон уничтожает ключевого коня g5 с шахом или нападением на ферзя. Белые остаются без фигуры без какой-либо компенсации. В этой структуре правильный план — 3.Qd3!, создавая батарею по диагонали b1–h7 и связывая слона защитой пункта h7!»*

#### Пример 2: Пассивный шах при короле на $g6$
* **Позиция**: $1.Bxh7+\;Kxh7\;2.Ng5+\;Kg6$
* **Ошибка белых**: $3.Qg4?$
* **Опровержение черных**: $3...f5!\;4.Qg3\;f4!\;5.Bxf4\;Rxf4!\;6.Qxf4\;Qxg5$
* **Объяснение**: *«Неточность, выпускающая инициативу. Шах ферзем на g4 дает черным спасительный тычок f7-f5 с темпом. Черный король ускользает в безопасную зону. Правильный ход Вуковича — 3.h4!, строящий матовую сеть и угрожающий смертельным вскрытым шахом 4.h5+ Kh6 5.Nxf7+ с выигрышем ферзя!»*

#### Пример 3: Попытка атаки без пешечного клина $e5$
* **Позиция**: Конь черных все еще имеет доступ к $f6$.
* **Ошибка белых**: $1.Bxh7+?$
* **Опровержение черных**: $1...Kxh7\;2.Ng5+\;Kg8\;3.Qh5\;Nf6!$
* **Объяснение**: *«Жертва слона некорректна! У черных есть конь на d7/e7, который успевает занять пункт f6 и намертво перекрыть вертикаль h и диагональ мата. Жертва слона допустима только тогда, когда пункт f6 надежно отрезан белой пешкой e5!»*

## 4. Трехуровневая прогрессивная система подсказок (Hint Ladder)

Тренажер использует методику поэтапного педагогического наведения, исключающую бездумное списывание:

```
[Пользователь затрудняется с ходом]
               │
               ▼ Нажатие «Подсказка 1»
┌────────────────────────────────────────────────────────┐
│ Уровень 1: Стратегическая концепция (Concept Hint)     │
│ • Текстовое описание идеи Вуковича                     │
│ • Координаты и фигуры НЕ раскрываются                  │
│ • Штраф к очкам за шаг: -15%                           │
└────────────────────────────────────────────────────────┘
               │
               ▼ Нажатие «Подсказка 2»
┌────────────────────────────────────────────────────────┐
│ Уровень 2: Подсветка фигуры и поля (Highlight Hint)    │
│ • Подсвечивается поле фигуры или поле назначения       │
│ • Янтарное пульсирующее свечение                       │
│ • Штраф к очкам за шаг: -40%                           │
└────────────────────────────────────────────────────────┘
               │
               ▼ Нажатие «Подсказка 3»
┌────────────────────────────────────────────────────────┐
│ Уровень 3: Конкретная стрелка и ход (Direct Move Hint) │
│ • Зеленая стрелка хода на доске                        │
│ • Точный ход в нотации SAN и краткое тактическое резюме│
│ • Штраф к очкам за шаг: -75%                           │
└────────────────────────────────────────────────────────┘
```

### 4.1. Детализация уровней подсказок

1. **Уровень 1 (Концептуальный)**:
   * *Задача*: Включить логическое мышление ученика.
   * *Примеры*:
     * «Отрежьте королю черных дорогу назад по шестой горизонтали с помощью крайней пешки.»
     * «Постройте матовую батарею, но выберите диагональ, недоступную для контрударов черного слона.»
     * «Создайте неотразимую угрозу вскрытого шаха с выигрышем тяжелой фигуры.»
2. **Уровень 2 (Тактический фокус)**:
   * *Задача*: Сузить пространство поиска до одной конкретной фигуры или критического сектора доски.
   * *Визуализация*: Кастомные стили `customSquareStyles` в `react-chessboard`:
     * Поле фигуры-источника: `boxShadow: 'inset 0 0 12px 3px rgba(245, 158, 11, 0.85)'`
     * Поле-мишень: `backgroundColor: 'rgba(251, 191, 36, 0.4)'`
3. **Уровень 3 (Прямое указание)**:
   * *Задача*: Помочь игроку выйти из полного тупика и продолжить упражнение.
   * *Визуализация*: `customArrows: [['h2', 'h4', 'rgb(34, 197, 94)']]` + всплывающий баннер с ходом: «Сыграйте 3.h4!».

## 5. Архитектура конечного автомата (State Machine)

Движок тренажера строго формализован как конечный автомат (FSM), что гарантирует отсутствие гонок состояний, дублирования ходов и некорректных вызовов FEN.

### 5.1. Диаграмма состояний

```
               ┌────────────────────────┐
               │          IDLE          │
               └───────────┬────────────┘
                           │ (initStudy)
                           ▼
               ┌────────────────────────┐
        ┌─────►│   WAITING_USER_MOVE    │◄─────────────────┐
        │      └───────────┬────────────┘                  │
        │                  │ (onPieceDrop)                 │
        │                  ▼                               │
        │      ┌────────────────────────┐                  │
        │      │  EVALUATING_USER_MOVE  │                  │
        │      └───────────┬────────────┘                  │
        │                  │                               │
        │     ┌────────────┼────────────┐                  │
        │     │ Best       │ Alt        │ Blunder          │
        │     ▼            ▼            ▼                  │
        │ ┌─────────┐ ┌─────────┐ ┌────────────────────┐   │
        │ │  STEP_  │ │  STEP_  │ │ANIMATING_REFUTATION│   │
        │ │ SUCCESS │ │ SUCCESS_│ └─────────┬──────────┘   │
        │ └────┬────┘ │   ALT   │           │              │
        │      │      └────┬────┘           ▼              │
        │      │           │      ┌────────────────────┐   │
        │      └─────┬─────┘      │MISTAKE_EXPLANATION │   │
        │            │            └─────────┬──────────┘   │
        │            ▼                      │ (retryMove)  │
        │     [Последний ход?]              └──────────────┘
        │      ├── Да ──► [STUDY_COMPLETED]
        │      └── Нет
        │            │
        │            ▼
        │ ┌────────────────────────┐
        │ │ANIMATING_OPPONENT_MOVE │
        └─┴──────────┬─────────────┘
                     │ (animationEnd ~500ms)
                     └─────────────────────────────────────┘
```

### 5.2. Таблица переходов состояний

| Текущее состояние | Событие (Trigger) | Условие (Guard) | Следующее состояние | Действие (Action) | Блокировка доски |
|---|---|---|---|---|:---:|
| `IDLE` | `LOAD_STUDY` | Валидный ID этюда | `WAITING_USER_MOVE` | Установка начального FEN, запуск таймера хода | Нет |
| `WAITING_USER_MOVE` | `PIECE_DROP` | Ход фигурой белых | `EVALUATING_USER_MOVE` | Замер времени шага, сравнение с деревом вариантов | **Да** |
| `EVALUATING_USER_MOVE` | `MOVE_EVALUATED` | Ход совпадает с `bestMove` | `STEP_SUCCESS` | Начисление очков, анимация зеленой волны, звук успеха | **Да** |
| `EVALUATING_USER_MOVE` | `MOVE_EVALUATED` | Ход в `alternativeMoves` | `STEP_SUCCESS` | Начисление очков с пометкой, показ комментария | **Да** |
| `EVALUATING_USER_MOVE` | `MOVE_EVALUATED` | Ход в `inaccuracies` | `WAITING_USER_MOVE` | Отмена хода, показ предупреждения о неточности | Нет |
| `EVALUATING_USER_MOVE` | `MOVE_EVALUATED` | Ход в `blunders` или вне дерева | `ANIMATING_REFUTATION` | Применение хода белых, подготовка хода черных | **Да** |
| `STEP_SUCCESS` | `CHECK_COMPLETION` | Шаг был последним в этюде | `STUDY_COMPLETED` | Остановка общего таймера, расчет финального скоринга | **Да** |
| `STEP_SUCCESS` | `CHECK_COMPLETION` | Есть следующие ходы | `ANIMATING_OPPONENT_MOVE` | Запуск таймера анимации (~500мс) | **Да** |
| `ANIMATING_OPPONENT_MOVE`| `ANIMATION_END` | Ход черных совершен на доске | `WAITING_USER_MOVE` | Смена FEN, очистка подсказок, старт таймера шага | Нет |
| `ANIMATING_REFUTATION` | `REFUTATION_PLAYED` | Ход черных показан на доске | `MISTAKE_EXPLANATION` | Открытие панели разбора ошибки | **Да** |
| `MISTAKE_EXPLANATION` | `RETRY_STEP` | Пользователь нажал «Попробовать снова» | `WAITING_USER_MOVE` | Откат FEN к началу текущего шага | Нет |
| Любое | `TOGGLE_MODE` | Переключение в режим «Анализ» | `ANALYSIS_MODE` | Пауза тренировочного таймера, открытие полного дерева | Нет |

## 6. Метрики расчета и формула мастерства (Scoring Engine)

### 6.1. Математическая модель оценки качества расчета
Успех в атаке требует баланса между **глубиной расчета**, **чистотой первого выбора** и **контролем времени**. Быстрый необоснованный тычок в 1 секунду наказывается так же строго, как и зависание на 5 минут.

#### 1. Оценка отдельного шага ($S_i$):
$$S_i = S_{base} \times M_{quality} \times M_{hint} \times M_{attempts} \times M_{time}$$

Где:
* $S_{base} = 100$ очков.
* **Множитель качества ($M_{quality}$)**:
  * `best`: $1.0$
  * `alternative`: $0.90$
* **Множитель подсказок ($M_{hint}$)**:
  * Без подсказок: $1.0$
  * Подсказка 1 (Концепция): $0.85$
  * Подсказка 2 (Подсветка): $0.60$
  * Подсказка 3 (Стрелка/Ход): $0.25$
* **Множитель попыток ($M_{attempts}$)**:
  * Решено с 1-й попытки: $1.0$
  * Решено со 2-й попытки (после 1 ошибки): $0.50$
  * Решено с 3-й и более попытки: $0.25$
* **Множитель времени размышления ($M_{time}$)**:
  * $< 2.0$ сек (импульсивный клик): $0.95$ (легкий штраф за отсутствие расчета)
  * $2.0$ – $35.0$ сек (оптимальная зона вдумчивого расчета): $1.00$
  * $35.1$ – $75.0$ сек (глубокий, но затянутый расчет): $0.90$
  * $> 75.0$ сек: $0.75$

#### 2. Общая точность расчета в сессии ($A$):
$$A = \left( \frac{\text{Количество ходов, решенных с 1-й попытки без подсказок}}{\text{Общее число ходов белых в задании}} \right) \times 100\%$$

#### 3. Глубина чистого расчета ($D_{clean}$):
Количество полуходов подряд от стартовой позиции, выполненных пользователем без единой ошибки и без подсказок 2-го и 3-го уровней.
* Например, в 5-ходовой линии ($10$ полуходов): если пользователь безошибочно нашел ходы 1, 2 и 3, а на 4-м ошибся, то $D_{clean} = 6$ полуходов (3 хода белых).

#### 4. Итоговый балл мастерства расчета (Mastery Score, 0–100):
$$Score_{total} = \frac{\sum_{i=1}^{N} S_i}{N}$$

### 6.2. Квалификационные ранги мастерства атаки

| Диапазон баллов | Звание по Вуковичу | Описание уровня расчета |
|:---:|---|---|
| **92 – 100** | 🏆 **Гроссмейстер атаки** | Безупречный расчет 5–7 ходов, видение тонких ходов (h4!, Qd3!), нулевой процент зевков |
| **78 – 91** | 🥇 **Мастер атаки** | Уверенное преодоление упорной защиты черных, мелкие неточности быстро исправляются |
| **60 – 77** | 🥈 **Кандидат в мастера** | Понимание основного лейтмотива, но периодические затруднения при контригре черных |
| **40 – 59** | 🥉 **Практик миттельшпиля** | Нахождение первого очевидного удара, но расчет глубины 3+ ходов хромает |
| **0 – 39** | 📚 **Рекомендуется разбор** | Требуется повторное изучение теоретической главы и дерева вариантов в режиме анализа |

## 7. Спецификация сохранения прогресса (localStorage Persistence)

Для обеспечения автономной работы тренажера без внешних серверных БД разработан строгий контракт хранения в браузере с версионированием схемы.

### 7.1. Ключи и схема хранилища
* Основной ключ: `vukovic_chess_storage_v1`
* Ключ сессии: `vukovic_active_session_v1`

```typescript
export interface VukovicStudyRecord {
  studyId: string;
  themeId: string;             // 'greek_gift', 'rook_lift', etc.
  completed: boolean;
  bestScore: number;           // 0 - 100
  bestAccuracy: number;        // 0 - 100%
  cleanDepth: number;          // макс. чистая глубина
  attemptsCount: number;
  lastCompletedAt: string;     // ISO timestamp
  mistakeHistory: {
    plyIndex: number;
    playedMove: string;
    refutationSeen: boolean;
  }[];
}

export interface VukovicUserStats {
  version: 1;
  totalStudiesCompleted: number;
  overallAccuracy: number;
  averageCalculationTimeSec: number;
  masteryPoints: number;
  currentStreakDays: number;
  studies: Record<string, VukovicStudyRecord>;
}

export interface VukovicActiveSession {
  studyId: string;
  stepIndex: number;
  elapsedSeconds: number;
  currentScoreAcc: number;
  stepAttempts: Record<number, number>;
  hintsUsed: Record<number, number>;
}
```

### 7.2. Отказоустойчивость и миграции
* **Защита от квоты (QuotaExceededError)**: при переполнении хранилища сессионные логи ошибок очищаются, сохраняются только агрегированные `bestScore` и флаг выполнения.
* **Идемпотентность и восстановление**: при случайном обновлении страницы (`F5`) активная тренировка восстанавливается из `vukovic_active_session_v1` с точностью до текущего хода.

## 8. UX переключения режимов («Изучение» vs «Тренировка расчета»)

Платформа решает критическую проблему UX: как объединить свободный анализ гроссмейстерских вариантов и жесткий проверочный экзамен в одном бесшовном интерфейсе.

### 8.1. Сравнительный анализ двух режимов

```
┌────────────────────────────────────────────────────────────────────────┐
│ [Вукович: Искусство атаки]   [📖 Режим изучения]  [🎯 Тренажер расчета] │
├───────────────────────────────────┬────────────────────────────────────┤
│                                   │                                    │
│       ШАХМАТНАЯ ДОСКА             │         ПАНЕЛЬ УПРАВЛЕНИЯ          │
│                                   │                                    │
│   • Интерактивная доска 8x8       │  В РЕЖИМЕ ИЗУЧЕНИЯ:                │
│   • Стрелки планов атаки          │  • Полное интерактивное PGN-дерево │
│   • Подсветка полей вторжения     │  • Переключение веток (2...Kg6/Kg8)│
│   • Свободное перемещение ходов   │  • Развернутый русский комментарий │
│                                   │                                    │
│                                   │  В РЕЖИМЕ ТРЕНАЖЕРА:               │
│                                   │  • Туман войны (Fog of War)        │
│                                   │  • Таймер размышления              │
│                                   │  • Счетчик глубины: «Ход 3 из 5»   │
│                                   │  • Кнопка ступенчатых подсказок    │
│                                   │  • Карточка ошибки при зевке       │
└───────────────────────────────────┴────────────────────────────────────┘
```

### 8.2. Механизм «Тумана войны» (Fog of War)
* В **Режиме расчета** будущее дерево ходов **полностью скрыто**. Пользователь видит только список уже сделанных ходов и текущий ход: `Ход 3: Белые начинают и выигрывают`.
* Никаких подсказок в нотации, никаких оценок движка Stockfish до завершения расчета.
* При переключении в **Режим изучения** по завершении сессии открывается полное дерево с текстовыми комментариями ко всем альтернативам и опровержениям.

## 9. Строгие контракты данных TypeScript (Engine Interfaces)

Для интеграции с фронтендом и датасетом спроектированы следующие типы:

```typescript
/** Уровень качества хода пользователя */
export type MoveQuality = 'best' | 'alternative' | 'inaccuracy' | 'blunder';

/** Уровень запрошенной подсказки */
export type HintLevel = 1 | 2 | 3;

/** Шаг расчета в цепочке атаки белых */
export interface CalculationStep {
  stepIndex: number;                  // 0, 1, 2...
  moveNumber: number;                 // 1, 2, 3...
  fenBefore: string;                  // FEN перед ходом белых
  expectedFenAfter: string;           // FEN после сильнейшего хода белых
  bestMoveSan: string;                // e.g. "h4"
  bestMoveUci: string;                // e.g. "h2h4"
  bestMoveExplanation: string;        // Почему этот ход лучший (русский язык)
  
  // Допустимые альтернативы
  alternativeMoves?: {
    san: string;
    uci: string;
    explanation: string;
  }[];

  // Типичные неточности
  inaccuracies?: {
    san: string;
    uci: string;
    explanation: string;
  }[];

  // Катастрофические ошибки с интерактивным опровержением
  blunders: {
    san: string;
    uci: string;
    refutationSan: string;            // Ответ черных (e.g. "Bxg5")
    refutationUci: string;            // e.g. "c8g5"
    refutationFen: string;            // FEN после опровержения
    explanation: string;              // Развернутое опровержение на русском
  }[];

  // Трехуровневая система подсказок
  hints: {
    level1Concept: string;            // Общая стратегическая идея
    level2Highlight: {
      fromSquare?: string;            // e.g. "h2"
      toSquare?: string;              // e.g. "h4"
    };
    level3Arrow: [string, string];    // e.g. ["h2", "h4"]
  };

  // Автоматический упорный ответ черных
  opponentResponse?: {
    san: string;
    uci: string;
    fenAfter: string;
    comment: string;
  };
}

/** Полная структура учебного этюда тренажера */
export interface CalculationStudy {
  id: string;
  title: string;
  theme: 'greek_gift_kg8' | 'greek_gift_kg6' | 'greek_gift_corner' | 'rook_lift' | 'f7_g7_destruction';
  difficulty: 'intermediate' | 'advanced' | 'master';
  initialFen: string;
  vukovicChapter: string;
  description: string;
  initialMovePrompt: string;
  steps: CalculationStep[];
}
```

## 10. Заключение и готовность к реализации

Предложенная архитектура полностью закрывает требования **R3** и критерии приемки:
1. **Глубокий расчет (3–7 ходов)** вместо примитивного угадывания первого хода.
2. **Интерактивное опровержение ошибок** с показом карающего ответа черных и разбором на русском языке.
3. **Честная 3-уровневая система подсказок**, мотивирующая к самостоятельному расчету.
4. **Устойчивый конечный автомат**, предотвращающий рассинхронизацию интерфейса и шахматного движка.
5. **Бессерверное сохранение прогресса** через `localStorage`, готовое к мгновенному деплою на Vercel.
