# Локальный nonchalant HUD на Mac

Прототип показывает только «Есть блестящая идея», когда ограниченная проверка
подтвердила кандидата по критериям nonchalant. Ход, фигура, оценка и варианты
остаются внутри движка. Это собственный критерий проекта, совпадение со значком
Chess.com не гарантируется.

## Запуск

```sh
cd /Users/user/teamwork_projects/vukovic_chess_attack
npm install
npm run hud:setup
npm run hud
```

После первоначальной установки достаточно `npm run hud`.

Для своего nonchalant откройте второй терминал, выполните `npm run dev` в той же
папке и откройте адрес localhost, напечатанный Next.js. В HUD выберите
«Из nonchalant», скопируйте ключ и вставьте его в меню **HUD** в шапке сайта.
Оставьте одну доску целиком видимой. Позиция приходит из состояния приложения,
включая сторону хода, рокировки и en passant. Ключ действует только до закрытия
приложения. После обновления сайта потребуется подключиться снова.

## Захват экрана

1. Выберите «Распознавание экрана», экран, затем точный квадрат доски без внешних
   рамок. Укажите цвет фигур снизу. Разместите HUD и окно настроек вне доски.
2. Покажите начальную позицию с той же темой и масштабом. Нажмите «Начать новую
   партию». При первой калибровке откроется редактор: сравните фигуры с кадром,
   подтвердите данные галочкой и нажмите «Обучить фигуры по этому кадру».
3. Для уже идущей партии вставьте **полный FEN из надёжного источника** в
   расширенных настройках, загрузите его в редактор, проверьте фигуры и все
   метаданные, затем подтвердите текущую позицию.
4. Следующие позиции принимаются только после устойчивого кадра и единственного
   легального перехода. Если пропущен ход, кадр неоднозначен или захват прерван,
   подтвердите полный FEN заново. Знакомая расстановка сама не начинает партию.
5. При изменении области, темы или масштаба обучите фигуры заново. При новой
   стандартной партии кнопка «Начать новую партию» явно подтверждает стандартные
   метаданные и сверяет кадр со стартовой расстановкой.

Если macOS запрещает захват: **Системные настройки → Конфиденциальность и
безопасность → Запись экрана и системного аудио**. Разрешите Electron или
приложение, из которого он запущен, и перезапустите HUD. Захват звука выключен.
Прямая передача из nonchalant не требует записи экрана.

## Управление и статусы

- `⌘⇧P` — пауза; `⌘⇧H` — свернуть; `⌘⇧M` — переместить/закрепить;
  `⌘⇧N` — явно начать новую стандартную партию.
- Закреплённый HUD пропускает все клики. Настройки доступны через значок `!!`
  в строке меню. Закрытие окна настроек сохраняет работу HUD.
- «Проверяется», «Проверено», «Позиция не распознана» и «Проверка не завершена»
  различаются. Последний статус не выдаёт завершённый отрицательный результат.
- Уведомление выдаётся один раз для позиции за сеанс. Смена кадра/позиции снимает
  старый сигнал. Звук по умолчанию выключен.

## Проверка кандидатов и ограничения

Используются `inspectSacrifice`, `verifyBrilliantMove` и очередь/парсер
`BrowserChessEngine` из основного приложения. Проверяются материальная уступка
после немедленного обратного взятия, качество предложения, все допустимые
принятия жертвы, сильнейшая защита после предложения и выигрышные альтернативы.
Одна высокая оценка или одна линия MultiPV не дают сигнал.

Stockfish 19 Lite работает локально: один поток, 32 МБ hash, минимум 600 тысяч
узлов и глубина 12 для проверяемых поисков; MultiPV — 1,2 миллиона узлов.
Одна позиция ограничена 28 поисками и 60 секундами. После сбоя выполняется одна
повторная попытка новым процессом. Смена позиции убивает устаревший процесс.
Кэш хранит до 128 результатов на 10 минут.

Проверка рассматривает до трёх наиболее перспективных структурных жертв фигур.
Пешечные, позиционные жертвы без немедленного принятия и некоторые нестандартные
идеи будут пропущены. «Проверено» означает, что этот ограниченный поиск завершён;
отсутствие сигнала не доказывает отсутствие блестящего хода.

Распознавание привязано к калиброванной теме. Оно не гарантирует работу со всеми
скинами, перекрытиями, анимациями и качеством изображения. Доска под чужим окном
должна считаться неопределённой; предпочтителен прямой мост. FEN не содержит
историю троекратных повторений: экранный трекер учитывает её только с момента
подтверждения, а мост — там, где владелец доски передаёт признак конца партии.

## Воспроизводимые проверки

```sh
npm run test:hud
npm --prefix hud run test:game
npm --prefix hud run test:game:raster
```

`test:game` проигрывает полную партию Ласкер — Бауэр из
`content/course-build/Lasker-selected.pgn`: проверяет полный FEN после каждого
полухода, локальный мост и настоящий Stockfish с рабочими бюджетами. Утверждение
проверяет сигнал перед 15-м ходом белых. Отчёт: `hud/test-results/game-replay.json`.

`test:game:raster` рисует все позиции той же партии настоящими SVG-фигурами
react-chessboard в Chromium в двух ориентациях. Он запрещает уверенно неверную
расстановку и требует распознавания положительной контрольной позиции.
Отчёт: `hud/test-results/game-raster.json`.

Это воспроизведение записи партии и растровых кадров, а не сыгранная на сайте
онлайн-партия. Прогон `smoke` проверяет настоящие окна Electron, локальный HTTP,
Stockfish, короткий сигнал, его отзыв и восстановление настроек после перезагрузки.
Результат разрешения macOS печатается отдельно; без него живой захват недоступен.
