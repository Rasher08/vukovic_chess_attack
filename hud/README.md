# Tal HUD Mentality · 0.1.9

HUD показывает только «Есть сильная жертва», когда ограниченная проверка
подтвердила достаточную компенсацию. Ход, фигура, оценка и варианты остаются
внутри движка. Кандидату не обязательно быть единственным или первым выбором
Stockfish: достаточно сохранять как минимум примерное равенство. Это отдельный
профиль Tal HUD Mentality; он не пытается предсказать значок «!!» Chess.com.

## Ходы Chess.com

Основной источник теперь текстовый: распакованное расширение Chrome читает
только пронумерованную главную линию списка ходов. Stockfish и реконструкция
партии работают в локальном приложении. Запись экрана не нужна.

1. В приложении выберите **«Ходы Chess.com» → «Открыть папку расширения»**.
2. В Chrome откройте `chrome://extensions`, включите режим разработчика,
   нажмите «Загрузить распакованное расширение» и выберите эту папку.
3. Обновите страницу Chess.com. Скопируйте ключ из HUD, откройте расширение
   на вкладке партии, вставьте ключ и нажмите «Подключить эту партию».
4. Для стандартной партии оставьте обычное начало. Для своей начальной позиции
   укажите полный FEN **до первого записанного хода**. Это явная настройка,
   а не догадка по видимому фрагменту списка.

HUD запоминает ходы по абсолютным номерам полуходов; повторные сообщения их
не дублируют. Если сайт скрывает старые строки, они остаются в памяти. Если
подключение началось с середины неполного списка, один раз прокрутите к началу,
затем вернитесь в конец. Разрыв в истории, незаконный SAN, просмотр старого хода,
скрытая вкладка и недоступный источник снимают сигнал. Изменение старого хода
требует явного переподключения партии; незнакомые ходы не угадываются.

История хранится в памяти HUD, в том числе при коротком обрыве расширения;
после перезапуска HUD полный список читается заново. Ключ расширения хранится
только в сессионном хранилище Chrome и не передаётся скриптам страницы.
Одна вкладка подключается явно; посторонние вкладки и варианты движка не читаются.
Для новой партии подключитесь заново. Расширение передаёт текст только на
`127.0.0.1:18319/moves`; ответ содержит состояние синхронизации и число ходов.

Разметка проверена на настоящих страницах анализа и игры с ботом Chess.com
31 октября 2026: `wc-move-list` и `wc-simple-move-list`. Изменение сайта,
нестандартная разметка, варианты и некоторые режимы игры могут потребовать
обновления адаптера. Сквозной запуск расширения в настоящем Chrome на Windows
и рейтинговая партия этим прогоном не проверялись.

**Анализ движком во время партии против людей нарушает
[Fair Play Chess.com](https://support.chess.com/en/articles/8568369-what-do-i-need-to-know-about-fair-play-on-chess-com),
даже если выводится только короткий сигнал. Незаметность и отсутствие блокировки
не гарантируются.**

## Запуск

```sh
cd /Users/user/teamwork_projects/vukovic_chess_attack
npm install
npm run hud:setup
npm run hud
```

После первоначальной установки достаточно `npm run hud`.

Для своего nonchalant откройте второй терминал, выполните `npm run dev` в той же
папке и откройте адрес localhost, напечатанный Next.js. В HUD выберите
«Из nonchalant», скопируйте ключ и вставьте его в меню **HUD** в шапке сайта.
Оставьте одну доску целиком видимой. Позиция приходит из состояния приложения,
включая сторону хода, рокировки и en passant. Ключ действует только до закрытия
приложения. После обновления сайта потребуется подключиться снова.

## Захват экрана

1. Выберите «Распознавание экрана», экран, затем точный квадрат доски без внешних
   рамок. Укажите цвет фигур снизу. Разместите HUD и окно настроек вне доски.
2. Покажите начальную позицию с той же темой и масштабом. Нажмите «Начать новую
   партию». При первой калибровке откроется редактор: сравните фигуры с кадром,
   подтвердите данные галочкой и нажмите «Обучить фигуры по этому кадру».
3. Для уже идущей партии вставьте **полный FEN из надёжного источника** в
   расширенных настройках, загрузите его в редактор, проверьте фигуры и все
   метаданные, затем подтвердите текущую позицию.
4. Следующие позиции принимаются только после устойчивого кадра и единственного
   легального перехода. Временная неоднозначность скрывает позицию, сохраняя
   последний достоверный якорь. Возврат к ней или один легальный ход восстанавливает
   отслеживание. Пропуск нескольких ходов или обрыв захвата требует нового FEN.
   Знакомая расстановка сама не начинает партию.
5. При изменении области, темы или масштаба обучите фигуры заново. При новой
   стандартной партии кнопка «Начать новую партию» явно подтверждает стандартные
   метаданные и сверяет кадр со стартовой расстановкой.

Если macOS запрещает захват: **Системные настройки → Конфиденциальность и
безопасность → Запись экрана и системного аудио**. Разрешите Electron или
приложение, из которого он запущен, и перезапустите HUD. Захват звука выключен.
Прямая передача из nonchalant не требует записи экрана.

## Управление и статусы

- `⌘⇧P` — пауза; `⌘⇧H` — свернуть; `⌘⇧M` — переместить/закрепить;
  `⌘⇧N` — явно начать новую стандартную партию.
- Закреплённый HUD пропускает все клики. Настройки доступны через значок `♞`
  в строке меню. Закрытие окна настроек сохраняет работу HUD.
- «Проверяется», «Проверено», «Позиция не распознана» и «Проверка не завершена»
  различаются. Последний статус не выдаёт завершённый отрицательный результат.
- Уведомление выдаётся один раз для позиции за сеанс. Смена кадра/позиции снимает
  старый сигнал. Звук по умолчанию выключен.

## Своя музыка уведомления

В настройках раскройте **«Звук уведомления» → «Добавить свои файлы…»**.
Выберите один или сразу несколько файлов MP3, WAV, OGG, M4A, AAC или FLAC.
В библиотеке может быть до 20 треков: до 12 МБ каждый, до 120 МБ суммарно.
Готовых музыкальных треков в приложении нет. Каждый файл проверяется настоящим
медиаплеером перед добавлением; повреждённые файлы пропускаются с объяснением,
исправные сохраняются. Отмена диалога ничего не меняет.

Оставьте **галочки только у нужных треков** — например, у трёх из десяти.
Один отмеченный звук играет сам; несколько — выбираются случайно только
среди отмеченных. Повторы возможны. **«Стандартный сигнал»** имеет отдельную
галочку: снимите её, чтобы тон не попадал в музыку. При пустом выборе — тишина.
Добавление первой музыки снимает выбор стандартного тона. Выбор сохраняется.
Настройте громкость, **1–600 секунд** или **«До конца трека»**, затем флажок
**«Останавливать музыку после сделанного хода»**. Длительность и остановка
работают вместе: при включённом флажке ход прервёт даже полное воспроизведение.
При выключенном музыка продолжится в следующих корректно полученных позициях.
Пауза, выключение звука, смена источника и потеря позиции останавливают её.
Короткие треки заканчиваются естественно, не зацикливаются.

**«Прослушать»** работает и без подключённой доски; **«Стоп»** прекращает звук.
Для уведомлений включите **«Звук»** в верхней панели. По умолчанию он выключен.
Музыка играет с начала один раз при подтверждённом сигнале. Пока трек играет,
следующие сигналы не перезапускают его и не накладывают второй звук.
Скрытое окно настроек не мешает воспроизведению.

Файлы копируются в хранилище приложения и никуда не отправляются; исходники
можно переместить. Библиотека и настройки сохраняются между запусками, а старый
одиночный трек переносится при обновлении. **«Удалить»** возле трека удаляет одну
копию из HUD. **«Стандартный сигнал»** включает короткий тон, сохраняя библиотеку.
Для YouTube и Яндекс Музыки нужен локальный аудиофайл.

## Проверка кандидатов и ограничения

Профиль Tal HUD Mentality использует общие средства chess.js и Stockfish проекта,
но проверяет **корректную жертву**, а не узкий критерий блестящего хода сайта.
Другие хорошие продолжения не блокируют уведомление. Имя приложения, ключи,
история подключения и хранилище своей музыки сохранены при смене оформления.

Рассматриваются пешечные жертвы, жертвы качества и фигур с чистым вложением
от одной пешки после лучшего немедленного обратного взятия. Обычные равноценные
размены и защищённые мнимые предложения не считаются жертвами. Для первой
проверки используются до трёх наиболее перспективных кандидатов.
Учитываются также сильные ходы, оставляющие другую фигуру под боем: например,
Bf7 при допускаемом Nxg4. Взятие этой фигуры требует такой же проверки
компенсации, как непосредственная жертва сходившей фигуры.

Кандидат должен сохранять достаточную компенсацию на глубине 22. Проверяются качество хода относительно лучшего,
все допустимые принятия жертвы и независимая сильнейшая защита после предложения.
Кандидат может быть близким к лучшему, а не первым в линии. «Проверяется» остаётся
до окончания всех проверок; предварительный положительный результат скрыт.

Под достаточной компенсацией понимается как минимум примерное равенство по
конечному поиску движка: оценка кандидата и проверенных принятий не ниже 0
за жертвующую сторону, отставание от лучшего — не больше 40 cp. Это не
математическое доказательство ничьей: более глубокий поиск может уточнить оценку.
Никакая привлекательность атаки сама по себе не заменяет эту проверку.
Проигрыш и неполный ответ движка не выдаются за подтверждённую жертву.

Для обновления с 0.1.4/0.1.5/0.1.6/0.1.7/0.1.8 полностью завершите старый HUD через меню в трее,
запустите новый EXE и вставьте новый ключ подключения. Расширение менять не
требуется. Сборка 0.1.9 доступна в [GitHub Releases](https://github.com/Rasher08/vukovic_chess_attack/releases/tag/v0.1.9)
и локально в `hud/release/`. Классификация блестящих ходов
в разборе сайта остаётся самостоятельным критерием.

Stockfish 19 Lite работает локально: один поток, 32 МБ hash. Короткий отбор
MultiPV использует 1,2 млн узлов; проверка задаёт глубину 22 с пределом
до 9,6 млн узлов на запрос. Проверяется фактически достигнутая глубина.
Одна позиция ограничена 36 поисками и 90 секундами. После сбоя выполняется одна
повторная попытка новым процессом; исчерпание глубины/бюджета без сбоя не повторяет
ту же работу. Смена позиции убивает устаревший процесс.
Кэш хранит до 128 результатов на 10 минут.

«Скопировать диагностику» в настройках копирует версию и фактические FEN
последних восьми сигналов. Список живёт только в памяти сеанса. В него не
попадают гипотетические ходы, оценки и ключ, ничего не отправляется автоматически.

Проверка рассматривает до трёх наиболее перспективных структурных жертв.
Позиционные жертвы без немедленного принятия и некоторые нестандартные идеи
будут пропущены. «Проверено» означает, что ограниченный поиск завершён;
отсутствие сигнала не доказывает отсутствие корректной жертвы.

Распознавание привязано к калиброванной теме. Оно не гарантирует работу со всеми
скинами, перекрытиями, анимациями и качеством изображения. Доска под чужим окном
должна считаться неопределённой; предпочтителен прямой мост. FEN не содержит
историю троекратных повторений: экранный трекер учитывает её только с момента
подтверждения, а мост — там, где владелец доски передаёт признак конца партии.

## Воспроизводимые проверки

```sh
npm run test:hud
npm --prefix hud run test:moves
npm --prefix hud run test:game
npm --prefix hud run test:game:raster
npm --prefix hud run test:reported-game
```

`test:game` проигрывает полную партию Ласкер — Бауэр из
`content/course-build/Lasker-selected.pgn`: проверяет полный FEN после каждого
полухода, локальный мост и настоящий Stockfish с рабочими бюджетами. Утверждение
проверяет подтверждение либо явно незавершённый поиск перед 15-м ходом белых
при более строгих требованиях глубины. Отчёт: `hud/test-results/game-replay.json`.

`test:game:raster` рисует все позиции той же партии настоящими SVG-фигурами
react-chessboard в Chromium в двух ориентациях. Он запрещает уверенно неверную
расстановку и требует распознавания положительной контрольной позиции.
Отчёт: `hud/test-results/game-raster.json`.

Это воспроизведение записи партии и растровых кадров, а не сыгранная на сайте
онлайн-партия. Прогон `smoke` проверяет настоящие окна Electron, локальный HTTP,
Stockfish, короткий сигнал, его отзыв и восстановление настроек после перезагрузки.
Результат разрешения macOS печатается отдельно; без него живой захват недоступен.
